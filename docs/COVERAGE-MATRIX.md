# Matriz de cobertura operacional

A matriz acompanha o diagnóstico de 12/11/2026. Os nomes nas tabelas omitem o prefixo comum `leads2b_`. As ferramentas preservam os envelopes das consultas, exceto os diagnósticos com campos de saída explícitos e o histórico entre chats, que devolve apenas referências com vínculo confirmado.

Os GETs assinalados como conferidos foram observados em leitura com token ou em código da interface, conforme indicado. Os dois POSTs de busca têm método, corpo e finalidade observados na interface, testes com mocks e leitura com token no escopo avaliado. As rotas internas permanecem experimentais. A [referência pública da Leads2b](https://developers.leads2b.dev/api/openapi) não é o contrato dessas rotas.

Os testes [operational-reads](../tests/operational-reads.test.ts) chamam o MCP e conferem método, parâmetros, retorno e erros com HTTP simulado. As referências nas outras linhas apontam para suites específicas. Um retorno vazio, um total do backend ou HTTP 200, isoladamente, não comprova cobertura, uso da função ou persistência.

A verificação local usa fixtures sintéticas. Os pilotos de gravação foram executados em oportunidades sintéticas autorizadas. A criação tipada de nota e atividade foi validada em uma oportunidade por ferramenta. As rotas seguem experimentais para outras contas, tipos ou fluxos. A ferramenta bruta mantém as regras existentes para POST, PUT, PATCH e DELETE. Somente os dois endpoints específicos de busca têm POST dedicado de leitura.
